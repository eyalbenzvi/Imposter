# מִתְחַזֶּה

**▶ לשחק: https://eyalbenzvi.github.io/Imposter/**

משחק מסיבות בשתי צורות: **מכשיר אחד** שעובר בין השחקנים, או **כל אחד בטלפון
שלו**. עברית מלאה עם ניקוד, RTL, מובייל-first. אין שרת, אין חשבונות, ואין עלות.

3–12 שחקנים, שם אחר לכל אחד. המשחק בוחר מילה סודית ונותן למתחזה מילה אחרת,
קרובה אך לא זהה. כל שחקן אומר בתורו מילה אחת שקשורה למילה שקיבל, ואז מדברים
ומצביעים.

## שתי דרכים לשחק

| | מכשיר אחד | כל אחד בטלפון שלו |
|---|---|---|
| חשיפת התפקידים | מעבירים את המכשיר, אחד-אחד | כולם במקביל, כל אחד על המסך שלו |
| סבב רמזים | דיבור או הקלדה, לפי תור | זהה — הרצועה על כל המסכים, הכפתור אצל התורן |
| הצבעה | מעבירים את המכשיר | **כולם בו-זמנית, בסתר** |
| ניחוש המתחזה | כולם רואים את אותן 4 מילים | רק המתחזה שנתפס רואה אותן |
| מעברים בין שלבים | מי שמחזיק מחליט | **רוב מוכן** מכריע |
| אינטרנט | לא נדרש אחרי הטעינה | נדרש |

מצב מכשיר-אחד לא השתנה. הכניסה למצב הרב-מכשירי היא כפתור במסך הפתיחה, וכל
הקוד שלו נטען רק אם לוחצים עליו.

## פרסום ב-GitHub Pages

הרפו כולל workflow ב-`.github/workflows/deploy.yml` שבונה ומפרסם בכל דחיפה
ל-`main`. הוא כבר מוגדר ורץ — האתר החי הוא
https://eyalbenzvi.github.io/Imposter/.

ב-fork או בריפו חדש נדרשת פעולה ידנית **אחת** לפני הריצה הראשונה:
**Settings → Pages → Build and deployment → Source: `GitHub Actions`**.
אין דרך לעשות את זה מתוך ה-workflow: יצירת אתר Pages דורשת הרשאת admin על
הריפו, ול-`GITHUB_TOKEN` אין אותה בשום הגדרת permissions (גם לא עם
`enablement: true`, שמחזיר `Resource not accessible by integration`).

ה-build משתמש ב-`base: './'`, כך שאותו build עובד גם מתיקיית שורש וגם מתת-נתיב
של פרויקט — אין מה להגדיר.

ה-workflow מריץ `validate:words` ו-`npm test` לפני ה-build, כך שמחסן מילים
שבור או לוגיקה שנשברה לא מגיעים לאוויר.

## ארכיטקטורה

```
src/
  game/          לוגיקה טהורה — אפס imports של React
    types.ts     ה-state, ה-actions, WordEntry
    reducer.ts   state machine: SETUP → REVEAL → CLUES → DISCUSSION →
                 VOTING → VOTE_RESULT → IMPOSTER_GUESS → GAME_OVER
    rules.ts     חוקי ניצחון, ספירת קולות, פרויקציות קריאה
    niqqud.ts    stripNiqqud — כל השוואה במשחק עוברת דרכו
    overlap.ts   "שתי המחרוזות האלה דומות מדי?" — SAME/TOKEN/CONTAIN/ROOT
    prng.ts      cyrb128 + mulberry32
    words/       קובץ JSON לכל קטגוריה + index.ts
  ui/            React של מכשיר-אחד. קורא ללוגיקה רק דרך dispatch
    components/settings/   פאנלי ההגדרות, משותפים לשני המצבים
  online/        מצב רב-מכשירי. נטען lazy, אפס שינוי ב-game/
    protocol.ts  הודעות + parse מחמיר לכל מה שמגיע מהחוט
    room.ts      מושבים, seatOrder קפוא, אימות לובי
    thresholds.ts מי נספר וכמה צריך
    view.ts      projectView — הגבול הביטחוני היחיד
    driver.ts    אימות כוונות, ספים, קיפול טרנזקציוני ל-reducer
    peer.ts      עטיפה מעל PeerJS. נקודת ההחלפה היחידה
scripts/
  validate-words.ts    npm run validate:words
  write-category.mjs   כתיבת קטגוריה מפורמט מופרד ב-|
  trim-category.mjs    הסרת ערכים ותיקון הרמזים שהצביעו עליהם
```

שכבת הלוגיקה בנויה כך שאפשר להוסיף עליה מצב אונליין בלי לגעת בה — וזה בדיוק
מה שקרה: `src/online/` נוסף בלי לשנות שורה אחת ב-`src/game/`.

- `reducer(state, action)` הוא **פונקציה טהורה**. אותו input מחזיר אותו output.
- **אין** `Math.random()` ו**אין** `Date.now()` ב-reducer. כל רנדומליות — בחירת
  המילה, בחירת הרמז מתוך ה-5, בחירת המתחזים, סדר התורות, מסיחי הניחוש —
  מגיעה כ-`seed` ב-payload ומיושמת ב-PRNG דטרמיניסטי בסדר קבוע. אותו seed
  מייצר בדיוק אותו משחק.
- ה-state הוא אובייקט אחד, serializable במלואו ל-JSON.
- מעבר לא חוקי בין phases זורק `InvalidTransitionError`.

## איך המצב הרב-מכשירי עובד בלי שרת

מכשיר המארח **הוא** השרת. הוא מריץ את אותו reducer ומשדר לכל שחקן תצוגה
מסוננת דרך WebRTC ישיר. הברוקר הציבורי של PeerJS משמש רק ללחיצת היד
הראשונית — מרגע ההתחברות המידע זורם בין המכשירים, ונפילה שלו לא משפיעה על
משחק שרץ. אין חשבון, אין deploy נוסף, אין עלות.

**הטריק שמאפשר אפס שינוי ב-`game/`:** שכבת הרשת אוספת **כוונות** ולא actions.
כשכולם הצביעו, ה-driver מתרגם את הכוונות ל-`CAST_VOTE` ומשמיע אותן לפי
`voterOrder` — רצף חוקי לחלוטין מבחינת ה-reducer, שלא יודע ששום דבר השתנה.
אותו טריק מקפל את סבב החשיפה. בדיקה ב-`driver.test.ts` מוודאת שמשחק דרך
ה-driver ומשחק במכשיר אחד עם אותו seed מגיעים לאותו `GameState` בית-בית.

שני מונים שומרים על הסנכרון: `epoch` עולה רק כשהוחלו actions ומשמש כמפתח
שדוחה כוונות ישנות, ו-`version` עולה על כל שינוי ומפעיל שידור — כך המונים
החיים ("4 מתוך 6 הצביעו") זזים בלי לפסול כוונות תקפות.

`projectView` הוא הקוד היחיד שמחליט מה שחקן רואה. `GameState` גולמי לעולם לא
עולה על הרשת. שתי בדיקות שומרות על זה: אין הדלפה של המילה הסודית או של זהות
המתחזה באף phase, ובמצב סמוי ה-view של מתחזה ואזרח **deep-equal** אחרי איפוס
השדות הבודדים שאמורים להיות שונים.

פירוט מלא: `ONLINE_PLAN.md`.

## שני מצבי משחק

הבחירה היא שדה ב-state (`settings.mode`), לא flag ב-UI, ונחשפת ל-UI רק דרך
פרויקציה אחת: `getRevealView(state, playerId)`.

- **סמוי** (ברירת מחדל) — כל שחקן מקבל `kind: 'PLAIN'`. האובייקט שהמתחזה מקבל
  זהה מבנית לזה של אזרח; אין בו שום שדה שמסמן תפקיד.
- **גלוי** — המתחזה מסומן, אבל אף פעם לא לומד מי המתחזה השני. אין שדה שיכול
  לשאת את המידע הזה.

## איך המשחק מבטיח שרק אתם ראיתם את המילה שלכם

1. **חשיפה בלחיצה ממושכת.** המילה על המסך רק כל זמן שהאצבע עליו. הרפיה, מעבר
   לאפליקציה אחרת או שיחה נכנסת מסתירים אותה מיד — אי אפשר להעביר את המכשיר
   כשמילה פתוחה.
2. **מונה חשיפות ב-state.** כל חשיפה נספרת ב-`state.revealViews`. `SHOW_ROLE`
   הוא idempotent והזרימה לא חוזרת אחורה, לכן המונה תמיד עומד על 1 — צפייה
   שנייה היא בלתי אפשרית, לא רק לא מומלצת.
3. **ביקורת קבוצתית.** בסוף החלוקה מוצגת לכולם הרשימה עם המונה של כל שחקן,
   כך שהקבוצה רואה את אותם מספרים שכל שחקן ראה על המסך שלו.

## ניקוד

- פונטים: **Noto Sans Hebrew** ו-**Frank Ruhl Libre**, מאוחסנים בתוך הפרויקט
  (לא CDN). זה שתי המשפחות שממקמות ניקוד נכון — לא Heebo ולא Assistant.
- `line-height` מינימום 1.6 בכל אלמנט שמציג מילה מנוקדת, ובלי `overflow: hidden`
  או גובה קבוע על מכולות טקסט.
- `stripNiqqud` מסיר `[֑-ׇ]`, וכל השוואה, dedup ובדיקת שוויון עוברים
  דרכו. אין עמודת `plain` מקבילה בנתונים — תמיד גוזרים בזמן ריצה.
- כל המחרוזות מנורמלות ל-NFC.

## מחסן המילים

`WordEntry = { id, word, hints[5], category }` — המילה וכל 5 הרמזים בניקוד מלא.
הרמז הוא מילה אחת (או צירוף שמני של עד 2 מילים) מאותה קטגוריה, ביחס אח-לאח.

`npm run validate:words` נכשל על סכמה שגויה, מספר רמזים שאינו 5, `id` כפול,
מילה כפולה בין קטגוריות (בהשוואה **ללא** ניקוד), מילה או רמז ללא ניקוד, רמז
שזהה למילה שלו או לרמז אחר באותו ערך, קטגוריה עם פחות מ-100 ערכים, מחרוזת שאינה
NFC, ורמז שקיים גם כערך אך מנוקד אחרת.

### אף שני פריטים בערך אחד לא דומים מדי

המילה, חמשת הרמזים ושלושת ה-clues מגיעים כולם לאותו שחקן, ולכן `overlap.ts`
פוסל כל זוג מתוכם שחולק חומר גלוי לעין. ארבע הצורות, לפי סדר הדיווח:

| | | |
|---|---|---|
| `SAME` | אותה מילה בלי הניקוד | `כֶּלֶב` / `כלב` |
| `TOKEN` | חולקים מילה שלמה | `אוֹטוֹבּוּס` / `תַּחֲנַת אוֹטוֹבּוּס` |
| `CONTAIN` | אחת כתובה בתוך השנייה | `כֶּלֶב` / `כְּלַבְלַב` |
| | ההשוואה מילה־מול־מילה | `קָטָן` / `קַטְנוֹעַ`, `נַעֲלַיִם` / `נַעֲלֵי סְפּוֹרְט` |
| `ROOT` | אותו שורש | `קַצֶּפֶת` / `הַקְצָפָה` |

`ROOT` הוא היוריסטיקה, לא ניתוח מורפולוגי: אין כאן מילון שורשים, ולכן הקוד
מקלף את התחיליות והסופיות שהעברית באמת נוטה בהן ומשווה את מה שנשאר. הוא
**מסתעף** על כל קילוף במקום להכריע — ה-כ' של `כְּתִיבָה` היא גם מילת יחס וגם
אות שורש, ורק ענף אחד משני נפגש עם `כּוֹתֵב`. שתי אותיות לעולם לא מצטמצמות
לכלום, ולכן `פֶּה` ליד `שָׂפָה` עובר.

ההטיה היא לכיוון פסילה: זוג שנתפס בטעות (`כֶּבֶל` / `בֶּלֶם`) שווה ניסוח מחדש
בכל מקרה, בעוד זוג שהוחמץ עולה לאוויר ומסגיר את המילה.

התקדמות המחסן ואופן ההמשכה: `WORDS_PROGRESS.md`. האפליקציה עובדת גם עם מחסן
חלקי — אף מקום בקוד לא מניח מספר ערכים.
